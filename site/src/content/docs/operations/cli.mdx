---
title: Команда scilla
description: Справочник по команде управления сервером scilla.
---

Команда `scilla` без аргументов открывает меню в терминале: состояние, обновления, логи, доступ, сайты REALITY, ноды, бэкапы. Те же действия доступны командами. Сами команды на английском, запускаются от root.

## Сервер

| Команда | Что делает |
|---|---|
| `scilla status` | контейнеры, процессор и память, состояние панели, доступное обновление |
| `scilla doctor [--json]` | проверить сервер панели или ноды, у каждой строки подсказка, см. ниже. `--json` печатает отчёт в JSON без секретов |
| `scilla support <код> [--dry-run]` | отправить поддержке проверку, состояние и последние строки лога (секреты вырезаны) с кодом из вашего обращения, см. ниже |
| `scilla logs [panel\|node]` | логи в реальном времени, <kbd>Ctrl</kbd>+<kbd>C</kbd> останавливает |
| `scilla restart` | перезапустить контейнеры |
| `scilla api-lockdown [status\|off]` | на сервере ноды: состояние правила файрвола «API ноды только с IP панели» или снять его сразу, см. [Защита ноды](/scilla/nodes/hardening/) |
| `scilla support-access on\|off` | разрешить или запретить на этом сервере [доступ для поддержки](/scilla/operations/support-access/); `off` действует, что бы ни было в панели |
| `scilla update [--check]` | обновить сейчас, сначала бэкап, при сбое откат. `--check` только проверяет |
| `scilla install [флаги]` | установка, на установленном сервере открывает меню |
| `scilla uninstall [-y]` | остановить и удалить команду, данные остаются в `/opt/scilla` |

`scilla doctor` работает на сервере панели и на сервере ноды. Проверяет Docker и контейнеры, что порты слушаются, правила ufw для порта API ноды, порта панели и портов протоколов, синхронизацию времени (`timedatectl` и заголовок Date от github.com, допуск 30 секунд), DNS, выход по HTTPS на github.com и ghcr.io (нужны для обновлений), диск (✗ меньше 500 МиБ, ! меньше 2 ГиБ) и память. На ноде ещё раз отправляет «приветствие» панели и печатает результат. Каждая строка помечена ✓, ! или ✗ и содержит подсказку; если есть ✗, команда завершается с ненулевым кодом. `scilla status` сам предложит `scilla doctor`, когда что-то не так. Это инструмент для случая, когда панель не может достучаться до ноды совсем. Тот же набор проверок для сервера панели есть в самой панели: кнопка «Проверить сервер» в **Настройки → Система**.

Панель запускает `scilla doctor` и `scilla restart` на своём сервере, а на сервере ноды через API ноды, без SSH: она пишет файл-заявку в свою папку данных, а юнит systemd (`scilla-doctor-request.path`, `scilla-restart-request.path`, их ставит установщик и `scilla update`) выполняет команду и возвращает отчёт. Серверу, установленному до 0.5.2.0, для этого нужен один `scilla update`. Логи панели и нод тоже видны в панели, токены, ключи, пароли и ссылки подписок в них вырезаны. Всё это собрано на странице [Диагностика](/scilla/operations/diagnostics/).

`scilla support <код>` нужна, когда панель не работает или нода недоступна для панели. Возьмите код из своего обращения в поддержку и выполните команду от root: она соберёт тот же отчёт, что `scilla doctor --json`, вывод `scilla status` и последние 300 строк логов контейнеров, вырежет секреты и отправит один JSON в службу поддержки (`SCILLA_SUPPORT_URL` направит его в другое место). Файлы настроек (`config.json`, `secrets/`, а на старых серверах `.env`), ключи и сертификаты не читаются и не отправляются. `--dry-run` печатает, что было бы отправлено, и ничего не отправляет.

## Файлы настроек

:::note[Секреты вне .env: 0.5.2.0]
Раньше все настройки сервера лежали в `/opt/scilla/.env`. С версии 0.5.2.0 они разделены, а секретов в окружении контейнеров больше нет: `docker inspect` и `/proc/<pid>/environ` показывают только пути к файлам.
:::

| Путь | Что там | Права |
|---|---|---|
| `/opt/scilla/config.json` | обычные настройки: образ, версия, режим, `SCILLA_ACME_LISTEN`, `SCILLA_AUTO_UPDATE` и другие. JSON-объект из строк | только root |
| `/opt/scilla/secrets/` | секреты, каждый отдельным файлом: `postgres_password` и `database_url` (пароль и адрес базы на сервере панели), `node_join` (ключ подключения на сервере ноды) | папка 0700, каждый файл 0400 и читается только контейнером, которому он нужен |

Docker Compose подключает файлы из `secrets/` к контейнерам как secrets (`/run/secrets/<имя>`). Панель и нода читают пароль, адрес базы и ключ ноды оттуда. Бэкап хранит и `config.json`, и `secrets/`, а старые архивы с `.env` восстанавливаются как раньше.

**Следующий `scilla update` переносит существующий `.env` сам**: сначала создаёт новые файлы, а `.env` удаляет, когда scilla уже работает на них. Копия остаётся в бэкапе обновления. Откат на старую версию scilla возвращает `.env` на место. Ничего делать руками не нужно.

Чтобы поменять обычную настройку вручную, поправьте `config.json` и выполните `scilla restart`. Например, чтобы nginx или Caddy на порту 80 пропускали проверки сертификата к scilla, добавьте в `config.json` строку:

```json
{
  "SCILLA_ACME_LISTEN": "127.0.0.1:18080"
}
```

(вместе с остальными строками файла, через запятую). Значения попадают в `compose.yaml` как есть, поэтому в них нельзя `$`, кавычки, пробелы и `#`. Секреты правятся только через панель и команды scilla: `scilla join KEY` на ноде меняет `node_join`. Команда `scilla cert proxy <домен>` сама пропишет `SCILLA_ACME_LISTEN` и перезапустит ноду.

## Доступ

| Команда | Что делает |
|---|---|
| `scilla url` | ссылка на панель и логин |
| `scilla reset-password` | новый пароль администратора, все сессии, API-ключи и ключи доступа (passkey) отзываются |
| `scilla reset-path` | новая секретная ссылка, старая перестаёт работать |
| `scilla disable-2fa` | выключить 2FA, если потерян телефон |

## Бэкапы

| Команда | Что делает |
|---|---|
| `scilla backup` | бэкап в `/opt/scilla/backups` |
| `scilla restore FILE [-y] [--no-db-snapshot]` | восстановить из бэкапа, см. [Бэкапы](/scilla/operations/backups/) |
| `scilla move USER@HOST [-p SSH_PORT] [--force] [--stop-old] [--dry-run] [-y]` | перенести панель на новый сервер по SSH: бэкап, установка там с тем же портом панели, восстановление, порты в ufw. `--dry-run` только печатает шаги, `--stop-old` в конце останавливает панель здесь, `--force` заменяет данные scilla, если он на новом сервере уже стоит. См. [Перенос scilla на другой сервер](/scilla/start/migrate/#перенос-scilla-на-другой-сервер) |

## Ноды и подключения

| Команда | Что делает |
|---|---|
| `scilla node list` | ноды панели |
| `scilla node add --name NAME --host IP [--domain D] [--api-port P]` | добавить ноду и получить ключ |
| `scilla node key NODE` | новый ключ ноды, старый перестаёт работать |
| `scilla node set NODE [--name] [--host] [--domain] [--enabled=true\|false]` | изменить ноду |
| `scilla join [KEY] [--panel-ip IP]` | на ноде: принять новый ключ из панели |
| `scilla inbound list` | подключения |
| `scilla inbound add PRESET [--port PORT] [--node N]` | добавить подключение, без пресета покажет список |
| `scilla inbound set NAME --port PORT [--node N]` | сменить порт, ключи и маскировка остаются |

Своя нода панели имеет номер 1, её адрес и домен меняются в настройках панели.

## Сертификаты

| Команда | Что делает |
|---|---|
| `scilla cert set --cert fullchain.pem --key privkey.pem [--node N]` | свой сертификат панели или ноды |
| `scilla cert show [--node N]` | что стоит сейчас |
| `scilla cert clear [--node N]` | вернуть автоматический сертификат (для ноды: самоподписанный) |
| `scilla cert proxy <домен>` | порт 80 держит nginx или Caddy: пропустить через него проверки центра сертификации к панели или ноде (правило с бэкапом, проверкой конфига и перезагрузкой) |

## Сайты маскировки REALITY

| Команда | Что делает |
|---|---|
| `scilla targets scan [--node N] [--json]` | найти подходящие сайты рядом с сервером |
| `scilla targets check --dest HOST:PORT [--sni NAME]` | проверить сайт |
| `scilla targets apply --dest HOST:PORT [--sni NAME] (--all \| --inbound NAME) [--force]` | поставить сайт всем подключениям или одному |

Для IP-адреса в `--dest` нужен `--sni`. Сайт проверяется перед применением, `--force` пропускает проверку.

## Адаптеры оплаты

| Команда | Что делает |
|---|---|
| `scilla addon list` | что работает и что есть в каталоге |
| `scilla addon install ID` | поставить или обновить адаптер |
| `scilla addon remove ID` | остановить и удалить, настройки и платежи в панели остаются |
